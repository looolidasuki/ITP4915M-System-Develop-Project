## 2. Relationships Summary

The diagram relies heavily on **One-to-Many ($1:\dots$ or $1:N$)** and **Many-to-Many ($M:N$)** relationships:

* **B2BCustomer to Contacts/Addresses:** One customer can have multiple contact persons and multiple delivery locations ($1:N$).
* **Sales Processing:** A `SalesOrder` can have multiple `Product` lines ($M:N$, broken down via `SalesOrderProductLine`).
* **Fulfillment & Invoicing:** A `SalesOrder` generates a `DeliveryNote` for shipping. The `InvoiceLine` links back to the `DeliveryNote`, meaning invoices are generated based on actual physical shipments.
* **Production & Materials:** A `Product` is built from multiple `RawMaterials` ($M:N$ via `ProductRawMaterial`). If an order cannot be fulfilled by current warehouse inventory, a `ProductionOrder` is triggered.
* **Procurement:** A `PurchaseOrder` buys `RawMaterials` from a `Supplier`. Once delivered, it maps directly to a `GoodsReceivedNote` to update physical stock.

## 3. Important Notes Extracted from Diagram Text

The ERD includes embedded business logic notes crucial to how developers should code the system:

1. **Warehouse Reservation Logic (Sales Order Line):** > `"warehouseReservedQty": If user inputs a value to hold qty from warehouse, then will know how many shortage.`
* *Meaning:* This field acts as an inventory lock. If you reserve stock for a high-priority customer order, the system subtracts this from available stock to calculate if a manufacturing shortage exists.


2. **Shipping & Delivery Updates:**
> `"shippedQuantity", default "0" -> DeliveryNote get salesOrder Products, user input shipped qty in DN, then update shippedQuantity, when all salesOrderProductLine.quantity = shippedQuantity, salesOrder.status = finished.`


* *Meaning:* A workflow trigger. When goods are shipped via a Delivery Note, the `shippedQuantity` updates on the Sales Order line. The moment your total shipped items match the original ordered quantity, the system automatically flips the overall `SalesOrder` status to **"Finished"**.


3. **Production Calculation:**
> `productionQty = this.salesOrderProductLine.quantity - this.warehouseReservedQty`


* *Meaning:* Formula for factory output requirements. If a customer orders 100 units, and you only have 40 units locked in the warehouse (`warehouseReservedQty`), the `ProductionOrder` must dynamically create a run for exactly 60 units.


4. **Shortage Report:**
* The `ShortageReport` is a Database View (`<<View>>`). It is not a permanent table but a dynamic query that cross-references required raw materials versus what's currently in the `RawMaterialWarehouse` to flag what the purchasing agent needs to order.
